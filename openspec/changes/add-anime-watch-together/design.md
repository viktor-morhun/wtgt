# Design

## Context

Мотивация описана в proposal.md. Что выяснено о внешних системах (проверено 2026-10-27):

- `anilibria.tv/release/<alias>.html` отдаёт старую страницу. Данные берём из нового API: `GET https://anilibria.top/api/v1/anime/releases/<alias>` возвращает JSON с `name`, `poster` (относительный путь от `https://anilibria.top`) и `episodes[]`. У каждой серии есть `id`, `ordinal`, `name`, `duration` (секунды) и `hls_480` / `hls_720` / `hls_1080`. У `tokyo-revengers` 24 серии.
- HLS-плейлисты лежат на `cache.libria.fun` и содержат абсолютные ссылки на `.ts`. Сегменты отвечают 302 на `cache3.libria.fun/...?expires=…`. API, плейлисты и сегменты отдают `Access-Control-Allow-Origin`, равный Origin запроса, поэтому браузер может играть поток напрямую, без нашего прокси.
- Проект `d:\agency\tg` задаёт визуальный стиль (`apps/miniapp/src/styles.css`: токены `--bg`, `--surface`, `--surface-2`, `--text`, `--hint`, `--dim`, `--sep`, `--radius: 28px`, кривые `--spring`/`--ease`, зерно `body::before`) и способ деплоя на этот же VPS: Coolify с Traefik в сети `coolify`, `certresolver: letsencrypt`, сборка на сервере (ARM64).
- Папка `d:\agency\wtgt` пустая, кроме `openspec/` и `.env`. В `.env` лежит API-токен Coolify и адрес `http://79.76.37.180:8000`, но не в формате `KEY=value`. `gh` авторизован как `viktor-morhun`.

## Goals / Non-Goals

**Goals:**
- Работающий совместный просмотр в тот же день, без установки чего-либо у второго зрителя (нужен только браузер, ПК или телефон).
- Расхождение позиций между зрителями не больше ~1 с, в том числе на 2x.
- Один репозиторий, один контейнер, автодеплой по push.

**Non-Goals:**
- Комнаты, ники, чат, авторизация, история просмотра.
- Хранение состояния между перезапусками сервера.
- Проксирование или кэширование видео на нашем сервере.
- Поддержка других сайтов, кроме AniLibria.
- Автоматические тесты UI в браузере. Тестами покрываем только логику синхронизации и разбор ссылок.

## Decisions

### D1. Сайт, а не расширение
Расширение пришлось бы ставить обоим, в мобильных браузерах оно не работает, а встраиваться в чужой плеер AniLibria хрупко. Сайт открывается по ссылке на любом устройстве. Свой плеер возможен, потому что HLS доступен по CORS.

### D2. Стек: Node 24 + Fastify + `ws`, React 19 + Vite + `hls.js`, TypeScript
Тот же стек, что в tg, поэтому стиль кода и конфиги (prettier, tsconfig) переносятся без изменений. Socket.IO не нужен: событий мало, переподключение и ping пишутся в 30 строк поверх `ws`. Структура одного pnpm-workspace:

```
server/   Fastify: статика web/dist, GET /healthz, GET /api/release/:alias, WS /ws
web/      React-приложение
shared/   protocol.ts (типы сообщений + zod) и sync.ts (расчёт ожидаемой позиции)
```

В Safari на iOS `hls.js` не работает (нет MSE), там видео получает `src` с `.m3u8` напрямую: нативный HLS. Проверка `Hls.isSupported()`.

### D3. API AniLibria читает сервер, видео грузит браузер
Сервер ходит в API (таймаут 10 с, кэш в памяти на 10 минут на каждый алиас), а клиенту отдаёт урезанную модель `{alias, title, poster, episodes:[{id, ordinal, name, duration, hls:{480,720,1080}}]}`. Сервер всё равно должен знать список серий для автоперехода и для проверки команд «сменить серию» и «сменить релиз». Заодно один формат на клиенте и одна точка, которую чинить, если API поменяется.
Альтернатива — клиент ходит в API сам. Это быстрее на один шаг, но тогда сервер не может проверять команды.

### D4. Модель сессии и протокол
Состояние на сервере:

```ts
type Session = {
  alias: string; episodeId: string;
  paused: boolean; position: number;   // секунды на момент anchor
  anchor: number;                      // Date.now() сервера
  rate: number;                        // 0.5 | 1 | 1.25 | 1.5 | 2
  version: number;                     // +1 на каждое изменение
};
```

Сообщения клиента: `play`, `pause {position}`, `seek {position}`, `rate {rate}`, `episode {episodeId}`, `release {input}`, `ended {episodeId, version}`, `ping {t0}`.
Сообщения сервера: `state {session, by?: 'action'}`, `viewers {count}`, `pong {t0, server}`, `error {code, message}`.

На каждую команду сервер сначала «замораживает» текущую позицию (`position += (now − anchor)/1000 · rate`, если играет), затем применяет изменение, ставит `anchor = now`, увеличивает `version` и рассылает `state` всем, включая отправителя. Позиция `pause` берётся от клиента: на паузу нажимают, глядя на свой кадр. Расхождение больше 2 с с расчётной считаем мусором и отбрасываем в пользу расчётной.

`ended` принимается, только если `episodeId` и `version` совпадают с текущими. Так конец серии, замеченный обоими клиентами, переключает серию ровно один раз (сценарий «Конец серии»).

### D5. Синхронизация часов и коррекция позиции
Часы сверяем как в tg: при подключении 5 ping/pong, смещение берём по медиане (`offset = server − (t0 + rtt/2)`), потом повторяем раз в 30 с. Ожидаемая позиция: `expected = position + (serverNow − anchor)/1000 · rate`, если играет.
Цикл на клиенте раз в 500 мс и на `visibilitychange`: если `|video.currentTime − expected| > 1`, делаем жёсткую перемотку. Мягкую подстройку скоростью не делаем, потому что на 2x она заметна на слух, а порога в 1 с достаточно для требования.
Буферизация одного зрителя других не ждёт: после загрузки он догоняет перемоткой. Это проще и не даёт медленному соединению тормозить обоих.

### D6. Отправлять только намеренные действия пользователя
Нативные `controls` выключены, все команды уходят из обработчиков наших кнопок и клавиш. События `<video>` (`play`, `pause`, `seeked`) команды не порождают. Так нет эха, когда применение удалённого состояния вызывает событие, которое снова отправляется на сервер.
Исключение — нативный полноэкранный режим iOS, где управление системное. Пока `webkitDisplayingFullscreen` включён, события `play` / `pause` / `seeked` отправляем как команды, если мы не применяли удалённое состояние в последние 300 мс (флаг `applyingRemote`).

### D7. Качество — локальная настройка
Качество не входит в сессию. Оно хранится в `localStorage`, по умолчанию 720. При смене запоминаем `currentTime`, загружаем другой плейлист и перематываемся.
При фатальной ошибке `hls.js` один раз вызываем `recoverMediaError()`. Если не помогло, перезапрашиваем релиз, потому что ссылки могли устареть, и загружаем серию заново. Если и это не помогло, показываем «Не удалось загрузить видео» с кнопкой «Повторить».

### D8. UI и стиль
Переносим из tg `:root`-токены тёмной темы, зерно, кривые анимаций и шрифтовой стек. Светлую тему не делаем: тёмная лучше для видео. Компоненты пишем сами, без UI-библиотек:
- шапка: название тайтла, «N смотрят», точка связи и кнопка «сменить тайтл», которая открывает поле для ссылки;
- плеер `16:9`, скругление `--radius` вне полного экрана; оверлей-тост действий по центру; панель снизу с градиентом;
- список серий: на ширине от 900px колонка справа (`grid-template-columns: 1fr 340px`), ниже — список под плеером.

Полный экран — `requestFullscreen` на контейнере плеера. На iOS — `video.webkitEnterFullscreen()`.

### D9. Деплой: GitHub → Coolify
- Публичный репозиторий `viktor-morhun/wtgt` (секретов в коде нет), ветка `main`. Публичный репозиторий Coolify забирает без deploy key.
- Поддомен и приложение в Coolify пользователь добавляет сам (решение при запуске apply). В README описаны настройки: build pack `Dockerfile`, порт `3000`, health check `/healthz`. Домен в коде не зашит.
- GitHub Action только проверяет код (lint, typecheck, test, build). Автодеплой включается в Coolify.
- `.env` переписываем в формат `COOLIFY_URL=…`, `COOLIFY_TOKEN=…`. Он в `.gitignore`, рядом лежит `.env.example` без значений.
- `Dockerfile` многоступенчатый: `node:24-slim`, `pnpm build`, в рантайме только `server/dist` + `web/dist` + прод-зависимости, `HEALTHCHECK curl /healthz`. Сборка идёт на VPS силами Coolify.

Альтернатива: `docker compose` по SSH, как у tg. Отклонена: пользователь просил Coolify, и так не нужен SSH-ключ в CI.

## Risks / Trade-offs

- [AniLibria сменит API или закроет CORS для CDN] → разбор ответа только в одном модуле сервера. При закрытии CORS добавим прокси `/hls/*` на сервере; это отдельная задача, сейчас не делаем.
- [В ссылках есть `isWithVideoAds=1`, в будущем в поток могут вставить рекламу] → сейчас в плейлисте рекламных сегментов нет. Ссылки используем как есть.
- [Устаревание подписанных ссылок сегментов] → при ошибке перезапрашиваем релиз (D7).
- [На 2x и медленной сети зритель постоянно отстаёт и прыгает] → порог 1 с и перемотка только после `canplay`. Зритель может снизить качество. Индикатор «догоняем…» показывает, что происходит.
- [Перезапуск при деплое сбрасывает сессию] → принято: два зрителя заново выбирают серию. Позицию можно перемотать.
- [Кто угодно со ссылкой может управлять просмотром] → принято для MVP: ссылку знают двое. Домен не публикуем.
- [iOS-нативный полноэкранный режим обходит наши кнопки] → D6, ловим события с флагом `applyingRemote`.

## Migration Plan

Новый проект, миграций нет. Порядок выкатки: репозиторий → приложение в Coolify → первый деплой → проверка `/healthz` и просмотр с двух устройств → включение автодеплоя. Откат: Coolify хранит прошлые образы, их перезапускают через «Redeploy» нужного коммита или `git revert` с push.
